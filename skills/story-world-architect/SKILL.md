# 小说世界观架构师

让世界的特殊规则进入地域、生产、权力、组织、家庭和日常生活。内部推演要完整，读者成稿要有清楚的阅读推进；两者使用同一正典，采用不同编排。

## 选择任务与交付对象

任务模式：`create` 新建、`expand` 扩展、`audit` 审查、`repair` 修订、`evolve` 根据已发生剧情更新、`handoff` 交接大纲、`lock` 经用户确认锁版。

交付对象独立选择：

- `reader`：制作世界观、世界设定集或爱好者读物时的默认模式。用叙述式说明、少量生活事务片段和人物观察位置，帮助读者理解一个能运转的世界。
- `author`：用户明确需要规则圣经、内部百科、设定工程或完整作者手册时使用。展示规则编号、正典状态、运行条件、接口和必要台账。
- `handoff`：只交接大纲时优先制作稳定接口，不自动展开成一本读物。

`audit`、问答、目录核对或增量讨论按用户要求在对话中完成；只有本次任务包含文档交付才生成 DOCX。已确认的范围和授权继续有效，不重复询问。

深度按实际复杂度选 `compact / standard / deep`。制度密集题材可做 deep 研究与压力测试，但研究深度不决定成稿的术语密度或篇幅。模块按因果需要启用。

## 来源与正典

先盘点用户原稿、指定参考、当前正典、历史交付、已确认大纲和正文。以最新明确用户指令、用户指定权威/锁定版本、已发生正文事实、已确认计划、旧笔记及推断的顺序处理；来源矛盾须说明影响，不能静默选边。

内部区分 `hard / soft / belief / open / retired`，以及作者真相、公众/势力认知和角色可知范围。保留预测、可能、计划与已发生事实之间的差别。未经确认的数值、制度和人物结果不得悄悄成为硬规则。

已获批准的正典变更登记 `WCR-NNN` 后直接同步，不再索取同一授权。新的核心变更若超出授权，再提出具体选择和影响。锁版须用户明确确认；排版完成不等于正典锁定。

## 工作流程

### 1. 盘点并核对成稿方案

大型新建或重构先在对话中给出：核心命题与不可改规则、读者对象、舞台规模、按需细至四级的目录、分章篇幅预算、总字数口径、参考文件与排版方案。按用户要求确认后填充；用户已要求直接执行或已有确认方案时继续落实。

先核对四项创作锚点：现实/文化参照与表述要求、叙事基准时间与历史分岔、世界基调与救济尺度、货币与购买力口径。读 [design-anchors.md](references/design-anchors.md)；沿用已确认答案，未定项记为 `open`，允许相对时间和相对尺度，不为填表擅定公历年、政体、币值或保障水平。

同等规模的长篇读者设定集可参考四至六万汉字；短篇舞台和大型系列另作估算。汉字数、含标点字符数与页数分别报告，页数以实际渲染为准。不得照搬某个样本的章节数、人物数或页数。

阅读 [reader-edition.md](references/reader-edition.md) 设计 reader 目录、文风、人物和阅读节奏。初始化或维护内部正典时阅读 [world-contract.md](references/world-contract.md)；现有项目先建来源映射，不强制迁移目录。

### 2. 建立世界常态和规则后果

同时从类型体验、时代窗口与地理、资源、技术边界推演，检查：

`约束 → 分配 → 激励 → 制度或习惯 → 日常后果 → 持续压力 → 可能变化`

规则用稳定 `RULE-NNN` 记录。说明适用主体、成立条件、限制/例外、可观察证据和执行或反制；制度还要交代授权、成本、覆盖、失败、申诉、绕过和风险承担。

对改变社会的制度补上形成链：谁发起、旧办法卡在哪里、参与者为何接受、谁反对、为何持续，以及其他地区为何采用、改造或拒绝。算法估值、登记权利和真实生产分开解释；预测不会自行创造粮食、能源、资金或偿付能力。

审查规则的正常使用、失败与被利用的路径，必要时登记 `LOOP-NNN`。救济可以有效，也可以难以获得；按已确认基调解释受益者、成本与覆盖缺口，不自动用万能福利消除压力，也不强制每条规则产生犯罪。技术替代、资源变化会怎样冲击既有义务，须追到家庭、组织与制度的承受者。

若一项设定被称为世界规则，检查它在相关主体与地区之间怎样成立和履行，不能仅写成某个机构的产品。按本作需要检查个人、组织、公共机关等主体组合；不要把其他作品的贷款、魔法或身份规则移植进来。

### 3. 展开社会和时代

按题材需要覆盖地域与空间美学、生产与资源、公司或其他组织、职业、阶层、家庭、教育、照护、文化与休闲、国家政权、中央地方关系、暴力与执法边界、信息权限、历史与当下变化。

这些是覆盖检查，不是必须等长填写的表格。精确数值尚未确认时，可用明确基点和范围的相对尺度；同一参照不可跨章节漂移。

地域介绍尽早点明与主舞台的共同规则、制度差异和迁移后果，不只更换风景和名词。同一项权利或义务跨地区时，交代识别、互认、清算/履行、管辖与例外；不默认全世界制度一致。现实参照影响行政用语、组织和日常肌理，不机械套用西式政治框架，也不把某种政体或政治词禁表强加给所有作品。

势力 `FAC-NNN` 与制度 `INST-NNN` 应有资源、目标、约束、依赖、策略和决策机制。历史留下当前的边界、特权、创伤或未偿承诺。解释为什么旧均衡在此时承压，保留多种有代价的变化方向。

### 4. 写读者正文并控制节奏

按已确认目录写连续正文；先让人进入地点与事务，在相关位置完整交代核心规则。短片段提供可见条件和后果，说明交代常态、主体、过程和例外。

检查连续章节的信息强度与论证节奏。核心原则再次出现须增加新情境、新后果或必要例外。减少反复的合理性—问题—补救—代价—边界结构；允许景物、物件、风俗和普通活动承担世界质感，不要求每段收束成观点。

用中文里自然的主体与动作表达，修复抽象名词作主语、绕远的被动句和反复的“能做什么，不能替人做什么”判词。空间、机制、家庭、历史和人物可采用不同观察方式，不能全书套一种腔调。具体方法见 reader 规范；有用的技术词与真实限定不得为去腔调而删掉。

人物介绍以当前处境、日常活动、资源、关系和可选择空间为主；目录标题可标性别、年龄、职业/身份。少数人物可跨章节持续出现，保持事实和时间一致，不强制每章安排角色或给所有人完整剧情弧。对话、心理推进和悬念服从设定集用途。

### 5. 内部交接与语义审查

需要大纲接口时读 [outline-handoff.md](references/outline-handoff.md)，更新 `15_大纲接口.md`。结构冲突 `CON-NNN` 与剧情种子 `SEED-NNN` 留在内部；它们提供入口和可能性，不预定角色决定。已有大纲只做兼容检查，不覆盖故事 DNA、章纲或锁定计划。

当前世界状态与未来剧情计划分开维护。正文证实后才能把拟议变化写入当前状态；说明传播时延、二阶后果和可逆性。

读 [audit-rubric.md](references/audit-rubric.md) 分别做规则/因果审查与读者审查。先处理会污染正典的矛盾，再处理阅读顺序、重复论证、术语、人物工具化和篇幅。脚本只能核对结构、引用、文本及排版，不能证明制度或文学质量。

另查制度起源、技术与代际时间线、单位换算、地区反差及基调是否漂移。晚近技术的现实依据需要检索；未来扩散速度仍是作品推演。不要把现实预测、分位区间、世界内宣传或外部建议当成已确认事实。

硬规则变化时检查相关核心、技术、经济、法律、阶层、历史、势力、信息、冲突、种子、状态、索引、接口与 reader 正文；只改柜台例子不足以完成世界级变更。

### 6. 排版与最终交付

本次包含文档交付时读 [docx-delivery.md](references/docx-delivery.md)。有 documents 技能时遵守其制作和渲染要求；没有时使用文档中公开的 Python、LibreOffice 与 PDF 逐页渲染路线，不假定专属工具存在。用户模板优先；无新样本时使用本技能的干净读者模板和样式说明。

reader 成稿含封面、与实际正文对应的一至四级带页码目录和世界正文；只收录实际使用的层级，不为凑四级细分短段。内部编号、审计、WCR、版本日志、编制说明、draft 状态和大纲台账保存在项目文件及交付说明中，除非用户要求放入文档。补充知识采用世界内部的章节/标题编排。

审查源文覆盖、字体实际显示格式、目录与页码、跳转和文件完整性，渲染后逐页查看；最后一次修改须对应最后一次验证。默认只交付用户要求的最终 DOCX，内部 QA 文件保留供追踪。

## 工具与维护

- `scripts/init_world_project.py`：只创建缺失的内部正典文件与创作锚点；不覆盖原稿。
- `scripts/validate_world.py`：检查内部字段、锚点结构、ID 与引用（含按需使用的 LOOP/REG/CHAR）；兼容没有新锚点文件的旧项目。不审判政治词或自动判断文风。
- `scripts/lock_world.py`：仅在用户确认锁版时创建不可覆盖快照。
- `scripts/extract_reader_template.py`：从参考 DOCX 提取并清理可复用样式，记录实际显示格式；参考文件不变。
- `scripts/build_reader_docx.py`：从 reader Markdown 和模板生成最多四级目录/跳转的 DOCX，按渲染 PDF 同步页码。
- `scripts/verify_reader_docx.py`：核对源文、标题、目录页码、书签、模板格式和可测布局边界，告警章末稀疏页；视觉审查仍须人工完成。
- `scripts/render_pdf_pages.py`：将已导出的 PDF 渲染为逐页 PNG；不替代 DOCX 转换或视觉审查。

具体调用与支持范围见 [docx-delivery.md](references/docx-delivery.md)。新增或变更脚本须用不同题材、不同标题数量和长标题实测，不能绑定历史样本的段落数量。
