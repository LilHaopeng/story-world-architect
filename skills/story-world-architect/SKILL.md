# 小说世界观架构师

让世界的特殊规则进入地域、生产、权力、组织、家庭和日常生活。内部推演追求严密因果，读者成稿追求自然洗练的阅读推进与书籍质感；两者共享同一正典，采用不同编排。

> **核心治理原则（硬正典边界，松创作空间）**：只把真正支撑核心体验与不可违背因果的机制锁死为 `hard` 正典，次要民俗、器物与边角生活保持 `soft / open` 弹性，为下游大纲和正文留出临场生长空间，不搞百科全书式过度锁死；若为 5 万字以内单点脑洞短篇，可直接使用 `webnovel-short-studio` 的一页规则卡轻装启动。

## 语言与起笔约定

- **默认简体中文**：除非用户明确指定其他语言（或提供非中文底稿并要求沿用），对话讨论、内部正典文件与读者设定集正文默认使用**简体中文**。
- **多语种主动切换**：用户可随时指定用**英文（English）**、**繁体中文**或其他语言起笔。切换后将目标语言记入 `世界观索引.md`，采用目标语言的母语说明文体与修辞规范；生成英文设定集 DOCX 时，调用 `build_reader_docx.py --toc-title Contents --subtitle "World Compendium"` 同步目录标题与封面副标题。

## 选择任务与交付对象

任务模式：`create` 新建、`expand` 扩展、`audit` 审查、`repair` 修订、`evolve` 根据已发生剧情更新、`handoff` 交接大纲与正文、`lock` 经用户确认锁版。

交付对象独立选择：

- `reader`：制作世界设定集或爱好者读物时的默认模式。用自然流畅的叙述式说明、简短生活事务切片与清晰的人物观察位置，帮助读者进入一个真实运转的世界。
- `author`：用户明确需要规则圣经、内部百科或作者手册时使用。展示规则编号、正典状态、运行条件、接口和必要台账。
- `handoff`：向下游大纲与正文交接时，生成稳定接口与**语言与日常肌理切片**，不自动展开成整本读物。

`audit`、问答、目录核对或增量讨论直接在对话中完成；包含文档交付任务时再生成 DOCX。深度按实际复杂度选 `compact / standard / deep`。

## 来源与正典

先盘点用户原稿、指定参考、当前正典、历史交付、已确认大纲和正文。按“最新明确用户指令 → 用户指定权威/锁定版本 → 已发生正文事实 → 已确认计划 → 旧笔记及推断”的优先级处理；来源矛盾时指明影响并请用户决断。

内部区分 `hard / soft / belief / open / retired`，隔离作者真相、公众/势力认知与角色可知范围。已获批准的正典变更登记 `WCR-NNN` 后直接同步；锁版须经用户明确确认。

## 工作流程

### 1. 盘点并核对成稿方案

大型新建或重构先在对话中给出：核心命题与不可改规则、读者对象、舞台规模、按需细至四级的目录、分章篇幅预算、参考文件与排版方案。

核对四项创作锚点：现实/文化参照与表述要求、叙事基准时间（T0）与历史分岔、世界基调与救济尺度、货币与购买力口径。读 [design-anchors.md](references/design-anchors.md)；未定项记为 `open`，支持相对时间与相对尺度。

阅读 [reader-edition.md](references/reader-edition.md) 设计 reader 目录、文风、视觉节律与人物切面；维护内部正典时阅读 [world-contract.md](references/world-contract.md)。

### 2. 建立世界常态和规则后果

从类型体验、时代窗口与地理、资源、技术边界同步推演：

`约束 → 分配 → 激励 → 制度或习惯 → 日常后果 → 持续压力 → 可能变化`

对关键机制执行资源—权力反馈、条件化链式推演、公开价值与实际行为落差三项检查（见 [design-anchors.md](references/design-anchors.md)）。规则以稳定 `RULE-NNN` 记录适用主体、成立条件、限制/例外、可观察证据与执行反制；制度交代形成链、授权、成本、覆盖、失败、申诉与绕过路径（必要时登记 `LOOP-NNN`）。

### 3. 展开社会、地域与语言烟火

按题材需要覆盖地域与空间美学、生产与资源、组织与职业、阶层与家庭、教育与照护、文化礼俗、政权与执法边界、信息权限、历史债务与当下变局。

地域介绍尽早点明与主舞台的共享规则、制度差异和迁移后果（可登记 `REG-NNN`）。同时提炼本世界的**日常语言与器物肌理**（称谓敬语、市井俗谚、行业行话、饮食器物、时代出戏词禁区），让制度真正落在人嘴边和手头上。

### 4. 写读者正文并把控页面观感

按已确认目录撰写连续正文：先带读者进入具体地点与日常事务，再自然交代核心规则。

- **单世界声口与母语自然度（防千书一面与过度去味）**：写作前先按本世界题材与气质定调叙述声口（如冷峻史志、市井烟火、诡谲志怪或明快游记），避免所有设定集滑向同一副“克制政策散文腔”。优先让人、机构、物件作主语并发出动作，消除高频空主语、层层名词化与反复的“能做 X，不能替人做 Y”判词；**严禁搞机械禁词或一刀切句式禁令**，正常抽象限定、生动比喻与流利长句按需保留。
- **自然阅读呼吸（防机械套模）**：避免连续数页等长论述段造成的沉闷感，根据章节内容自然切换饱满说明、短生活事务切片、必要对照小表或风物白描；不强求固定比例，也不必每章套用“小切片→制度解释→边界总结”的单一三段式，更不要为了“去说明感”把本该一气呵成的机制阐释切碎。
- **人物生活位置**：人物介绍呈现当前处境、资源来路、非工作关系与可选择空间（内部可用 `CHAR-NNN` 追踪一致性，编号不进入 reader 正文）。

### 5. 下游交接与多维审查

需要向下游交接时读 [outline-handoff.md](references/outline-handoff.md)，更新 `15_大纲接口.md`：除了传递硬规则、结构冲突 `CON-NNN`、剧情种子 `SEED-NNN` 与信息边界外，同步填写**「语言与日常肌理切片」**，为 `story-prose-writer` 提供原汁原味的称谓、俚语、器物与违和词红线。

读 [audit-rubric.md](references/audit-rubric.md) 分别完成世界语义审查与读者连续阅读体验审查；必要时执行“无主角运行”与“移除核心设定”反事实检验。

### 6. 书籍级排版与最终交付

包含文档交付时读 [docx-delivery.md](references/docx-delivery.md) 与 [reader-layout.md](references/reader-layout.md)。默认模板采用 **A4 书籍开本、宋体正文 + 微软雅黑层级标题，以及墨黛蓝、黛蓝、玄青灰、赭石暗金的克制书籍配色**（用户提供参考文档时优先提取用户样式）。

生成带真实页码与书签跳转的四级目录 DOCX，导出 PDF 后运行 `verify_reader_docx.py` 并逐页渲染 PNG 检查字体、版面边界与章末留白，确保最终交付件兼具内容严谨度与出版物观感。

## 工具与维护

- `scripts/init_world_project.py`：非破坏性创建内部正典骨架与创作锚点（支持 `--lang`、`--mode`、`--audience`）。
- `scripts/validate_world.py`：校验内部字段、创作锚点、对象 ID 与跨文件引用。
- `scripts/lock_world.py`：经用户确认后创建不可覆盖的正典快照。
- `scripts/extract_reader_template.py`：从参考 DOCX 提取干净样式模板并清理元数据指纹。
- `scripts/build_reader_docx.py`：编译最多四级目录跳转的设定集 DOCX，支持 `--pages-from-pdf` 回填真实页码及 `--toc-title` 多语种目录标题。
- `scripts/verify_reader_docx.py`：核对源文覆盖、标题跳转、样式一致性、文字边界与章末稀疏页提醒。
- `scripts/render_pdf_pages.py`：将 PDF 渲染为逐页 PNG 供视觉验收。
