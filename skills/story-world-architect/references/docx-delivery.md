# 世界设定集 DOCX 交付

本次任务包含文档制作或更新时读取。核对、问答、仅审查或增量正典维护按用户指定形式完成，不额外强制生成 DOCX。

## 1. 确定交付对象

`reader` 是制作世界设定集的默认对象。正文按 [reader-edition.md](reader-edition.md) 组织，面向爱好者和休闲读者。`author` 用于用户明确要求的作者手册或规则百科；可采用内部模块和对象结构。

reader 默认由封面、一至三级带页码目录、世界正文构成。标题和正文不展示稿次、draft 横幅、编制说明、规则 ID、审计分数、WCR、修改经过或大纲接口。用户特别要求时再加入对应内容。补充知识以世界内部主题自然编排，避免另起作者答疑附页。

未锁定状态如实记在内部和交付回复中。正文不留 TODO、待填或其他制作占位符；仍未定的世界事实保留明确不确定性，或按已确认范围暂不展开。

reader 默认路径为 `交付/{项目名}_世界设定集.docx`；修订时保留历史交付并记录最新文件。author 可用 `交付/{项目名}_世界观作者手册_{版本}.docx`。文件版本命名不自动产生锁定正典。

## 2. 汇编范围与正典对账

内部记录本次交付对象、源版本/散列、启用模块、用户指定权威、读者正文及覆盖映射。建议 `阅读版/编排.md` 保存章序、篇幅预算和样式来源，`阅读版/覆盖.md` 保存下列映射；沿用已有项目文件也可以。

| 有效设定或主题 | 源位置 | 正文主要落点 | 收录方式或未收录理由 |
|---|---|---|---|

reader 核对语义覆盖：核心规则的适用主体、成立条件、执行、重要例外与后果，以及本次应展开的社会/空间内容都要可找到。内部同一规则的重复字段、研究过程、备选种子和审计记录可以不收入正文，须有内部理由。不得为了简洁删掉会改变规则含义的条件。

author 完整汇编按对象 ID 集合核对 RULE、INST、FAC、HIST、CON、SEED、WS；按请求收录必要研究、审计、变更与接口。历史、废弃和冲突材料标明状态，不能混作当前事实。

读者正文新增并采用的事实回写正典；正文、模块、索引和接口的关键条件保持一致。确定本次源文快照后再生成，无需因此锁定正典；内容修改后重新核对与排版。

## 3. 样式与模板

有 documents 技能和工作区依赖加载器时使用它们，并遵守其制作、操作标记和渲染要求。普通环境可使用 Python 3.10+ 和本技能的 requirements.txt；DOCX 转 PDF 需另行具备 LibreOffice 或保留标题书签的其他导出器。本技能不分发专属 documents 渲染器、Office 软件或字体。用户指定模板/样本为设计权威，读取其实际显示格式；局部 run 属性可能覆盖 Word 样式默认值。无新样本时用 `assets/reader-template.docx` 和 [reader-layout.md](reader-layout.md)。

本技能默认样式是用户确认的阅读排版：微软雅黑正文 12 磅，一/二/三级标题 18/16/14 磅，目录项实际显示为 12/11/10.5 磅；页面几何、缩进、段距、行距、配色、页眉页码从模板继承。标题保留真实 Heading 1—3 样式，便于导航。人物标题默认含性别、年龄和职业/身份。

封面、标题、目录及正文的 ascii、hAnsi、eastAsia、cs 字体槽位都应正确设置；清除会意外覆盖样式的旧主题或局部格式。不能只改 font.name 后假定中文字体现已统一。用户样本含多分节、图像、复杂表格或控件时按 documents 模板流程定点修改，不用基础构建器重建它。

## 4. 通用辅助脚本

以下命令中的 `python` 指已安装依赖的解释器；有依赖加载器时使用其返回的绝对路径。脚本从可写工作目录运行，`<skill-dir>` 为本技能目录。

### 提取另一个参考样式

```text
python <skill-dir>/scripts/extract_reader_template.py --reference <参考.docx> --out <工作目录>/reader-template.docx --evidence <工作目录>/artifact.json
```

适用于本技能这类单分节、纯文本设定集。保留页面与角色样式，清理原正文、目录、书签和项目元数据，将标题/副标题/页眉换为通用槽位。实际标题字号、颜色等局部格式归入样式，记录参考散列和样式证据。复杂参考由脚本拒绝时，转入 documents 的模板保真流程，不能静默丢弃功能。

### 构建 reader DOCX

输入 UTF-8 Markdown：第一行 `# 书名` 为封面标题。正文可统一使用 `# / ## / ###`，或 `## / ### / ####`；构建器按正文最低标题层级归一为 Heading 1—3，不可混用两种约定或跳级。普通段落为空行分隔，支持简单无序/有序列表、行内强调和 Markdown 比较表；不支持的语法会明确拒绝，不能静默遗漏。复杂插图、数学或特殊版面按 documents 扩展。正文不要包含内部台账。

```text
python <skill-dir>/scripts/build_reader_docx.py --source <正文.md> --out <成稿.docx>
```

默认使用随技能安装的模板。`--template <另一干净模板.docx>` 采用已提取的同槽位模板；`--subtitle` 可改副标题。初次构建的目录页码只供排版，不能直接交付。

有 documents 时使用其 `render_docx.py --emit_pdf` 渲染到新 QA 目录；普通环境可执行 `soffice --headless --convert-to pdf --outdir <新QA目录> <成稿.docx>`。确认 PDF 由当前文件导出并保留标题大纲，再按实际标题页码重建：

```text
python <skill-dir>/scripts/build_reader_docx.py --source <正文.md> --out <成稿.docx> --pages-from-pdf <初次渲染.pdf>
```

重渲染到另一个新目录，核对最终 PDF。若页码变化，再同步并渲染至稳定；禁止把旧 PDF 当新文档的验证证据。构建器按当前标题和段落动态工作，不含固定数量要求。

### 结构与页码核对

```text
python <skill-dir>/scripts/verify_reader_docx.py --source <正文.md> --docx <成稿.docx> --pdf <最终渲染.pdf> --report <QA.json>
```

脚本核对正文、表格、标题/目录层级、目录页码、内部跳转、模板样式、修订痕迹和可测文字边界，报告字体与稀疏页供人工复核。`--template` 与构建器一致。脚本通过不证明阅读质量，也不代替逐页视觉检查。

## 5. 渲染与验收

有 documents 时使用当前包的渲染器和依赖运行时，不依赖历史安装版本路径。没有时将 DOCX 导出为 PDF，再执行 `python <skill-dir>/scripts/render_pdf_pages.py --pdf <最新PDF> --out <新的页面目录>`。每次迭代用新的输出目录，避免旧 PNG 残留被当作当前页数。

最终逐页查看 PNG，检查字体替换、缺字、裁切、重叠、长标题换行、目录对齐、孤立标题、单段孤页、异常大空洞、表格跨页与页眉页脚。缩略图可帮助定位，不能代替最终页的原尺寸检查。修复后重新渲染受影响页面；目录同步后确认全册页码稳定。

Windows 控制台出现 UnicodeDecodeError 时，先按需设置 UTF-8 输出，再核实 PNG/PDF 是否实际生成；不能只凭终端信息认定成败。渲染器不可用时保留文档，明确未完成视觉验收，不宣称成稿通过。

验收包含两个独立判断：世界语义与连续阅读检查通过；最终文件与渲染版一致。DOCX 正文没有制作占位符或非请求的修改记录，目录含用户要求的层级和真实页码。将路径、源版本/散列、日期、交付对象与 QA 状态写入内部工作状态。

## 6. 交付回复

默认交付一个最终 DOCX，简述本次内容、排版验证和必要的未锁定状态。有 documents 时按其当前引用规范引用最终文件一次，否则使用所在产品支持的文件链接。PNG、PDF、脚本日志和审计台账留作内部验证，用户要求时再提供。
